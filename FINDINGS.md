## 2026-10-09 · Файл настроек, не прочитанный при старте и оставшийся на месте, перезаписывается умолчаниями [P1]
**Context:** адверсариальный разбор 2026-10-09 (линзы: настройки, UX, регрессии; подтверждено двумя скептиками и сверкой кода). `src/Program.cs:3224` `CatchUpWithFile`, `src/Config.cs:396-426` `Stamped`.
**What:** Когда `Config.Load()` возвращает `LoadError`, а файл остаётся на месте (`.bad` уже есть — «файл оставлен на месте»; ошибка не JSON — «файл не тронут»; не удался `File.Move` в `Keep`), `Stamped()` ставит `Stamp` = mtime этого же файла, и `ChangedOnDisk` = false. Пулы GUID с пустыми `Slots` пачкают конфиг, и `Housekeeping` на 15-м тике (а также `Persist`, выход, конец сеанса) получает от `CatchUpWithFile()` true без чтения и пишет умолчания поверх единственной копии настроек — пока окно второго тика ещё говорит, что файл не тронут. Регрессия 37a4fe0: до `Stamped` `ChangedOnDisk` был true, и запись отказывала.
**Proposal:** Считать файл непрочитанным, пока `LoadError` не null: в `CatchUpWithFile()` — `if (!_config.ChangedOnDisk && _config.LoadError is null) return true;`, иначе `Config.Read()`, при ошибке `false`; то же условие в ветке перечитывания `Persist()`. Либо признак «с диска не прочитан» в `Config`, который проверяет `Save()`. Тест в ConfigTests: `.bad` уже есть, файл битый → `LoadError`, файл на месте, предикат «перед записью перечитать» = true.
**Status:** open
