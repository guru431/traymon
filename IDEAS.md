# TrayMon — идеи развития

Собрано 2026-09-03 по итогам разбора (находки — в [FINDINGS.md](FINDINGS.md)). Каждая идея
помечена **ценой** в терминах проекта: *ноль* — событие или изменение на старте, на тике ничего
не добавляется; *фон* — работа в `Task.Run` по уже существующему расписанию; *тик* — добавляет
работу UI-потоку и **принимается только с замером** (CLAUDE.md, «Цена наблюдения»); *сборка* —
меняет только csproj/publish. Всё, что противоречит инвариантам CLAUDE.md, помечено явно.
Статус у всех — предложено.

## 1. Уменьшить цену (отрицательная стоимость)

- **I-01 · Замедлять тик при заблокированной или отключённой сессии.** По
  `SystemEvents.SessionSwitch` (`SessionLock`, `RemoteDisconnect`, `ConsoleDisconnect`) переводить
  `TickMs` 2 с → 30 с и не перерисовывать значки вовсе: их никто не видит. На сервере с отключённым
  RDP это большую часть суток; невидимая тревога всё равно никого не находит. Потребует перевести
  `ForgetAfterTicks` и фазы со счёта тиков на время. *Цена отрицательная.* Усиливает главный
  инвариант.
- **I-02 · Гистерезис цвета плашки** (F-37): снимать тревогу только ниже `warn − 3 % шкалы`. Убирает
  перерисовку + вызов в оболочку на каждом тике у метрики, гуляющей вокруг порога. *Ноль.*
- **I-03 · Uptime из `Environment.TickCount64`** (F-39): минус целый PDH-запрос и параграф в трёх
  документах. *Ноль.*
- **I-04 · Один `NIM_ADD` на создание значка** (F-30): конструктор принимает начальные
  текст/severity/подсказку/цвет цифр. Минус ~17 рендеров и ~33 вызова на старте, без серой вспышки.
  *Ноль.*
- **I-05 · Приоритет процесса: Normal для UI, background mode для фоновых задач.** `Priority 5` в
  задаче (F-33) и `THREAD_MODE_BACKGROUND_BEGIN` в воркерах SMART/smartctl/SNMP (свой `Thread`
  вместо `Task.Run`): UI не голодает под нагрузкой, тяжёлое остаётся низкоприоритетным по CPU и
  вводу-выводу. *Ноль.*
- **I-06 · Настройки GC: `ConcurrentGarbageCollection=false`, `TieredPGO`** — убирает фоновый поток GC
  и часть рабочего множества (48 МБ — то, в чём README признаёт проигрыш). *Сборка; замерить память
  и время старта.*
- **I-07 · `TickMs` в `TrayMon.json` только в сторону увеличения** (2 → 5 → 10 с) для тех, кому 0.5 %
  много: цена делится пропорционально, инвариант «период задаётся ценой» соблюдён, если запретить
  уменьшение. *Ноль; противоречит README «периоды не вынесены сознательно» — обсуждать.*
- **I-08 · Backoff для источников, которых нет.** ИБП без агента шлёт UDP и ждёт 1.5 с каждые 30 с
  вечно (на каждой машине без ИБП — по умолчанию `127.0.0.1`); `smartctl` без файла проверяется
  каждые 10 минут. После N неудач — опрашивать раз в 5 минут, «Опросить датчики сейчас» сбрасывает.
  *Отрицательная (фон).*

## 2. Честнее показывать состояние (событийно, ноль на тике)

- **I-09 · Журнал переходов тревог в «Диагностике».** Кольцо на 50 записей «12:03 Температура CPU:
  жёлтый → красный (87 °C)», пишется только при смене цвета плашки. Отвечает на «почему ночью было
  красное», чего сегодня не может ни одна часть программы. *Ноль.*
- **I-10 · Событие в Windows Event Log на критические переходы** (RAID `FAILING`, остановка
  вентилятора, ИБП на батарее, красное место на диске): один `EventLog.WriteEntry` на переход,
  переходы — раз в месяцы. Серверные админы подхватят существующим мониторингом без единого
  нового процесса. *Ноль.*
- **I-11 · Балуны на критические переходы**, по образцу ИБП: RAID-диск `FAILING`, остановившийся
  вентилятор, красное свободное место. Настройка `NotifyOnCritical` на значок, по умолчанию
  включена только для этих трёх. *Ноль.*
- **I-12 · Погасший значок хранит последнее значение и время в подсказке**: «— адаптер пропал из
  системы, последнее 12 Мбит/с в 14:20». *Ноль.*
- **I-13 · Причина «нет линка» отдельно от «адаптер пропал»** (F-22 (3)): `HashSet` инстансов PDH
  прошлого чтения, сравнение раз в 6 с. *Фон, микросекунды.*
- **I-14 · Деградированные состояния ИБП и износ батареи в severity** (F-16): AVR/байпас → жёлтый,
  `NeedsNewBattery` → жёлтый, остаток < 5 мин → красный. *Ноль.*
- **I-15 · Здоровье NVMe из того же `hw.Update()`**: LHM отдаёт `Percentage Used`, `Available Spare`,
  `Critical Warning`; сыплющийся NVMe важнее греющегося — тот же аргумент, что уже принят для RAID.
  Severity как у RAID: плохое здоровье → красный независимо от температуры. *Ноль (данные уже
  читаются раз в 62 с).*
- **I-16 · Сводный значок кликом открывает сводку, отсортированную по score**, а не по группам —
  чтобы верхняя строка отвечала на «что именно красное». *Ноль.*

## 3. Надёжность источников (фон)

- **I-17 · `smartctl -j` вместо регексов** (F-20): JSON закрывает атрибут 190, `FAILING_NOW`, NVMe и
  SCSI одним махом; `-n standby,0` не будит спящие HDD за RAID — опрос становится *дешевле*. Плюс
  настраиваемый аргумент сканирования (`Tools.SmartctlScan`, по умолчанию `--scan-open -d csmi`)
  для `megaraid`/`aacraid`. *Фон.*
- **I-18 · SNMP v2c + повтор без отсутствующих OID** (F-17): тот же один UDP-пакет, per-varbind
  `noSuchObject`; парсер уже понимает 0x80–0x82. *Фон.*
- **I-19 · Реинициализация NVML по `GPU_IS_LOST` и минимум по всем вентиляторам карты** (F-18).
  *Событие + 1–2 вызова на карту раз в 4 с (десятки мкс).*
- **I-20 · Температура NVMe через `IOCTL_STORAGE_QUERY_PROPERTY(StorageDeviceTemperatureProperty)`**
  без LHM Storage: без драйвера ядра и на большинстве систем без прав администратора. Сужает
  зависимость от WinRing0 (F-01/F-02) до одной температуры CPU. *Фон, один DeviceIoControl на диск
  раз в 62 с; замерить против `hw.Update()`.*
- **I-21 · LibreHardwareMonitorLib ≥ 0.9.5 (PawnIO)** — единственное полное закрытие F-01/F-02.
  Новое требование установки (PawnIO) в обе README; **обязательный замер** `ReadSlow` до/после —
  цена MSR и SuperIO через PawnIO иная. *Фон; замер.*
- **I-22 · AMD: fallback на `Tctl/Tdie`** (F-13) и **вентиляторы, увиденные вращающимися позже,
  добавляются** (F-12). *Ноль.*
- **I-23 · Задача планировщика через COM `Schedule.Service`** вместо `schtasks.exe` + XML в `%TEMP%`
  (F-03, F-04, F-34): нет файла, нет поиска exe по папке приложения, HRESULT вместо stderr, SID
  вместо имени. *Событие.*
- **I-24 · `FileSystemWatcher` на `TrayMon.json`** с дебаунсом 1 с вместо ручного «Перечитать
  настройки» и проверки `ChangedOnDisk`. *Событие.*
- **I-25 · `SystemEvents.SessionEnding` / `WM_QUERYENDSESSION`**: сохранить грязный конфиг и снять
  значки при выходе из системы. *Событие.*

## 4. Инструменты проверки и замера (только в тестовых режимах)

- **I-26 · «Диагностика» показывает настоящую цену**: `Process.TotalProcessorTime` с момента старта
  и за последний час, отдельно время UI-тика и время фоновых задач (`_poolTicks`), максимальный тик
  и его семейство. Это число, ради которого проект написан, и сегодня его можно получить только
  внешним скриптом. *Ноль (два `GetTimestamp` на фоновый опрос).*
- **I-27 · `--once` с тёплым проходом**: каждый источник читается дважды, печатается
  `cost, ms (cold / warm)` (F-50). Закрывает оговорку из трёх документов.
- **I-28 · `--once --icons --ticks N`**: несколько настоящих тиков с паузой `TickMs`, чтобы
  smoke-тест видел `Fade`, Dead→Alive, версии семейств и не мусорные rate-счётчики (F-35).
- **I-29 · Тестовый проект на чистую логику** (F-48): BER-парсер с крафтёными пакетами (включая тот,
  что вешал поток), `GuidPool` со сдвигом букв, `Stats`, `Config` round-trip с враждебным JSON,
  шкала `worst`, `DryRun` на заранее собранных `Readings`. *Ноль.*
- **I-30 · Проверка `--once` в CI-скрипте публикации** (`/github-push`): сравнивать вывод с README
  по формату строк — примеры в README отстали от кода уже дважды (F-44).

## 5. Пользователю

- **I-31 · Диалог порогов в единицах пользователя** для инвертированных метрик (заряд ИБП, об/мин
  вентилятора) через существующее `Metric.Inverted`; «Пороги…» скрыть у метрик с `NeverAlerts` по
  умолчанию (тома, uptime); у вентиляторов — галочка «Тревога при остановке» (F-15). *Ноль.*
- **I-32 · Порядок строк в подсказке**: «5 мин» перед длинной строкой единиц у сети/томов — при
  обрезке до 127 сейчас отрезается самая стабильная часть (F-43). *Ноль.*
- **I-33 · Свободное место ≥ 1000 ГБ — в ТБ с одним знаком**, единица в подписи (F-25). *Ноль.*
- **I-34 · Батарея ноутбука через `GetSystemPowerStatus`** — один syscall, значок «% заряда» с
  инвертированной severity, как у ИБП. Расширяет аудиторию публичного зеркала с серверов на
  ноутбуки. *Тик, ~1 мкс — замерить формально.*
- **I-35 · Commit charge в подсказке RAM** из того же `GlobalMemoryStatusEx`
  (`ullTotalPageFile − ullAvailPageFile`): отвечает на «почему всё свопится при 60 % RAM». *Ноль.*
- **I-36 · CSV-журнал по всем слотам**, а не по фиксированным девяти колонкам: `time;id;value`
  или широкая строка из `_order` — сейчас в журнал не попадают температуры дисков, вентиляторы,
  тома и top-io, то есть половина того, что нужно для «почему сервер тормозил ночью». *Ноль
  (тот же интервал ≥ 30 с).*
- **I-37 · Вычистить `runtimes/` (linux/osx/android) из publish** — README обещает «один exe плюс
  несколько DLL». *Сборка.*

## Что предлагалось и отклонено в этом разборе

- **Огрубление CPU до шагов 2–5 %** ради меньшего числа перерисовок: меняет продукт («одно число»
  становится «примерно число»); README обещает точные целые. Если возвращаться — только как
  настройка и с замером.
- **Трасса ядра для ввода-вывода по томам** — уже отклонено в README (5–10 % ядра), подтверждаю.
- **AMD/Intel GPU через LHM** — уже отклонено (68 мс); альтернативы (ADL/IGCL) — только свой
  P/Invoke и только с замером, как и записано в «Ограничениях».
