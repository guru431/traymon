# TrayMon — правила проекта

Мониторинг машины в области уведомлений Windows: одна иконка — одно число. Что показывает
и откуда берёт — [README.md](README.md). Здесь — правила и ловушки, которые нужно знать до
правки кода. Почему каждое правило такое (разборы ошибок, замеры, отвергнутые варианты) —
[docs/design-notes.md](docs/design-notes.md): читать, прежде чем что-то из этого «упрощать».

## Цена наблюдения — единственное преимущество продукта

- TrayMon дешевле HWiNFO64 + AIDA64: **0.52 % ядра против 15.8 % и 13.7 %** (17 иконок, 120 с).
  Правка, которая это съедает, обессмысливает проект: новый источник данных или более частый
  опрос обсуждается только вместе с замером.
- `out\TrayMon.exe --once` печатает цену каждого источника: `cost, ms (cold / warm)`. Прогонять
  до и после любой правки сенсоров. По холодному числу сборки не сравнивают; тёплое — первое
  приближение, решение — по процессу целиком.
- Перерисовка и вызовы в оболочку дороже сбора. Правка отрисовки — только с
  `TrayValueIcon.Renders`/`ShellCalls` из «Диагностики…» до и после (норма ≈ 1.5 вызова на тик
  на весь трей). В `--once --icons` они по построению нули: трей там не трогается.
- Две сборки сравниваются по [docs/measuring.md](docs/measuring.md): одновременный запуск с
  `--measure`, дельта `TotalProcessorTime` и TrayMon, и `explorer.exe`, одинаковый состав
  значков. Один прогон не доказывает ничего. `--measure` в обычной работе не применяется.
- Длительности тика и фоновых опросов в «Диагностике…» — секундомер, а не процессорное время:
  складывать их нельзя.

## Инварианты

### Значки и GUID

- **GUID иконок в `Program.cs` не менять и не перенумеровывать**: позицию значка Windows держит
  за парой «путь к exe + GUID». Суффиксы — блоками по десять, схема комментарием у массивов:
  `01-0C` одиночные (`0D-0F` свободно), `11-14` диски, `21-28` вентиляторы, `31-38` тома,
  `41-44` RAID, `51-57` сеть, `61-68` место, `71-7C` вторая и следующие видеокарты. Новый значок —
  следующий номер в своём блоке, новое семейство — свободный блок. Первые слоты `NetGuids`,
  `GpuGuids`, `VramGuids`, `GpuTempGuids`, `GpuFanGuids` повторяют GUID прежних одиночных иконок
  намеренно.
- Второй экземпляр отбирает значки у первого, поэтому он запрещён мьютексом
  `Local\TrayMon.SingleInstance` (кроме `--measure`).
- **GUID выдаёт только `GuidPool` ([Pure.cs](src/Pure.cs)) — по ключу источника, не по индексу.**
  Все десять пулов и любое новое семейство — через него. Источники режутся по числу слотов только
  в пуле: `Take(...)` и `Math.Min(count, ...)` в датчиках запрещены.
- Раздача записана: `IGuidStore` → секция `Slots` в `TrayMon.json`, `Release()` запись удаляет.
  Пулам отдаётся `TrayApp` (он пересылает в текущий `_config`), а не `_config`; `Adopt()` берёт
  `Slots` из памяти целиком.
- **Ключ источника — аппаратный:** GPU — хвост UUID из NVML, вентилятор — всегда `чип/имя`,
  одинаковые модели дисков нумеруются по серийникам, диск за RAID — по серийнику. Смена схемы
  ключа — только через `TrayApp.Migrate` → `Config.Rename`, иначе настройки теряются.

### Опрос

- Период задаётся ценой источника: константы `*EveryMs` в `TrayApp` — результат замеров. Они в
  миллисекундах по `Environment.TickCount64` (`Due(ref at, periodMs)`), не в тиках: тик даёт только
  гранулярность, возврат в сеанс поднимает `_catchUp`. «Никто не смотрит» экономит рисование, а
  не сбор.
- `Config.TickMs` — только 2000–60000, меньше отвергается. Периоды источников не настраиваются.
- Тяжёлое читается в `Spawn(...)` под флагом `_*RefreshRunning` (`Interlocked.Exchange`, не
  `bool`); пул-потоки на это время в `THREAD_MODE_BACKGROUND_BEGIN`. В `LhmSensor` из двух потоков
  не входить (`_gate`). Правила про фазы нет: совпадение двух фоновых задач допустимо.
- **Свежесть — часть данных.** Фоновый читатель публикует снимок и штамп (`Readings.SlowAt`,
  `DisksAt`, `RaidAt`, `UpsAt`, `SpaceAt`, `TopIoAt`, `GpusAt`, `IoAt`), семейства проверяют
  `Fresh`/`MaxAgeMs` (2 × период + 30 с).
- **Счётчик PDH стоит целого объекта**: `PdhCollectQueryData` собирает все упомянутые в запросе
  объекты. Добавляя счётчик, смотри на объект и меряй; `\Process(*)` живёт в отдельном запросе,
  uptime — из `GetTickCount64`.
- В семействах с версионированием **версия читается до данных**: фон пишет список, потом версию.

### Отрисовка

- Числа на иконках огрублены: целые (`Whole`, `Mb`, `MbitWhole`), обороты в тысячах (`Rpm`),
  место от 1000 ГБ в ТБ; десятые — только в подсказке (`Mb2`, `Mbit`). Округление от нуля
  (`Format.Round`), не банковское.
- Пятизначных чисел нет: семейство, дошедшее до `Format.IconCeiling`, переходит на единицу выше
  и пишет её в подписи. Пятый шаг шрифта в `Render` — только страховка.
- Цвет огрублён гистерезисом: тревога снимается ниже порога на 3 % шкалы.
- Подсказка уходит в оболочку только по `WM_MOUSEMOVE`/`NIN_POPUPOPEN`. Дедупликация перерисовки
  по огрублённому тексту и цвету — отдельный механизм, нужны оба.
- Значок создаётся готовым: конструктор `TrayValueIcon` получает текст, severity, подсказку и
  цвет цифр — один `NIM_ADD`.
- Тревога кодируется не только цветом: уголок на жёлтой плашке, два на красной.
- `Show()` заполняет `LastText`/`LastDetail` всегда, в оболочку отдаёт только включённые значки.

### Тревоги

- **Уровень тревоги считает только `Alarm.LevelOf`** (`-2` неизвестно, `-1` нет данных, `0/1/2`):
  для плашки, уголков, журнала, уведомления и сводного значка (максимум уровней). `TrayValueIcon`
  порогов не знает, ему передают уровень.
- `Alarm.Unknown` (−2) ≠ `Dead` (−1): аварийное первое состояние обязано уведомить. Все
  уведомления — через `Notify()`: `NotifyOnCritical`, журнал Windows, одно сообщение на событие.
- Шкала сводного значка `Scale.Score` кусочно-линейная: `[0, warn) → [0, 78)`,
  `[warn, crit) → [78, 100)`, `≥ crit → 100+`, потолок 999.
- Инверсии в `Metric`: `Inverted` (ИБП, батарея) — «Пороги…» показывает и принимает заряд, хранит
  `100 − x`. `StallAlarm` (вентиляторы) — severity 0/100, пункта «Пороги…» нет, вместо него
  `IconSettings.Stall`: любая остановка (по умолчанию), `zero-ok`, `off`; у вентилятора GPU без
  датчика оборотов тревоги по остановке нет. Свободное место не инвертировано (severity и пороги —
  «% занято») и дополнено `WarnGb`/`CritGb`: побеждает худшее, подсказка говорит какое.
- ИБП: работа от батареи — сразу красный, через `Notify`; байпас, AVR, замена батареи — жёлтый;
  остаток < 5 мин — красный, даже без заряда в ответе. `upsBasicOutputStatus` разбирается по коду
  в `UpsReading`: `unknown(1)` — неизвестно, байпасы 6/9/10/16/17, AVR 4/12.
- Батарея ноутбука: пороги заряда действуют при работе от батареи и при неизвестном питании.
  «От сети» — `ACLineStatus == 1` (255 — неизвестно, `OnBattery` — `bool?`). Заряд 255 —
  неизвестно (`Charge` — `double?`, значок сереет с причиной). «Батареи нет» — флаг 128 либо
  неизвестны и флаг, и заряд. Пустую severity не подставлять: `Record()` покрасит по заряду.
- Выключенная подсветка — `IconSettings.Alerts = false`, а не пороги `1e9`; в отрисовку `1e9` тоже
  не передавать (severity сыплющегося диска та же). Старая пара `Warn = Crit ≥ Alarm.Never`
  переносится в `Alerts = false` (`Config.Validate`, конфиг помечается грязным). Константа одна —
  `Alarm.Never`, `TrayApp.NeverAlerts` ссылается на неё.
- Пороги валидируются до изменения настроек, одинаково в диалоге и в `Config`: конечность
  (`double.TryParse` принимает `NaN`/`Infinity`), диапазон, warn < crit.

### Живость слота и меню

- **Нет ни значения, ни доказанного состояния — слот не живой.** `Record()` отмечает живым при
  числе **или** severity; `Show()` для неживого ничего не делает. `Fade()` серит неотмеченные,
  пишет причину и последнее значение со временем, обнуляет `Severity`, для включённого мёртвого
  слота создаёт серую иконку. Через `ForgetAfterMs` = 24 ч по стенным часам GUID уходит в пул —
  кроме последнего слота, несущего меню.
- Датчик при отказе сам обнуляет своё поле: `MemorySensor` — `MemLoad`, `GpuSensor` — пустой
  список (в `catch` и при `rc != 0`), `LhmSensor.RefreshDiskTemps` чистит кэш, каждый `Refresh*` в
  `TrayApp` в `catch` публикует пустой список и двигает версию.
- **Последний значок скрыть нельзя** — меню живёт на значках. `CarriesMenu` = включён, иконка есть
  **и оболочка её приняла**; проверяется в `SetEnabled()` и в `Fade()` перед возвратом GUID.
  `EnsureSomethingVisible()` намеренно спрашивает только `Enabled`: иначе занятая при логоне
  оболочка давала бы лишние значки и диалог каждый тик. Сообщение — один раз.

### Источники данных

- Сеть — десятичные мегабиты (делитель 10⁶); загрузка канала — `max(in, out)`, не сумма.
- Температуры дисков — `IOCTL_STORAGE_QUERY_PROPERTY`, без драйвера ядра и без прав: `PropertyId`
  = 52, заголовок ответа 24 байта, температура на смещении 26 (`StorageTemperature`).
  LibreHardwareMonitor — только износ и резерв NVMe, по модели. `DiskTemps()` сохраняет
  непересечённые результаты обоих источников; неоднозначное совпадение износа не получает.
- GPU — через NVML; `IsGpuEnabled = false` у LHM присвоено явно (68 мс против 4). CPU — со счётчика
  гипервизора, если он есть; выбор печатается в `--once` строкой `counter in use`.
- Ответ SNMP — враждебные данные. Сверка PDU, request-id и community отсекает чужие и устаревшие
  датаграммы, а **не** сквоттера на `127.0.0.1:161`; от него защищают границы TLV в одном месте,
  строгое продвижение курсора по varbind'ам и то, что соврать он может только про ИБП.
  Формулировать в коде и документах именно так.

### Настройки

- `Config.LoadError` (файл не прочитан: умолчания, reload отказывается, окно на втором тике) ≠
  `Config.LoadNote` (прочитан, что-то поправлено: строка в «Диагностике…» и `--once`).
- Смена схемы настройки или идентификатора **переносит** прежнюю запись, а не бракует её.
- `_configDirty` сбрасывается только после успешной записи; запись и при штатном выходе;
  `_firstRun` кончается после первого удачного сохранения. `Persist()` перечитывает изменённый
  снаружи файл и переносит только меняемую настройку; непрочитанный не перезаписывает —
  изменение остаётся в памяти, пользователю сообщение. Автоматические записи (`Housekeeping`,
  выход, конец сеанса, `EnsureSomethingVisible`) — через `CatchUpWithFile()`; недописанный файл не
  перезаписывается. `Housekeeping` стоит в тике раньше `PickUpConfigEdit`.
- Autoreload — через `Config.Read()`, который файл не трогает. `Load()` с переносом в `.bad` —
  только на старте, и существующий `.bad` не перезаписывается.

### Процесс с админским токеном

- Автозапуск — COM `Schedule.Service` строкой XML, без файлов. Задача создаётся только из папки,
  недоступной на запись обычному пользователю: `Autostart.InstallUnsafe` обходит всех предков до
  корня тома (у них маска уже: `DeleteSubdirectoriesAndFiles`, `ChangePermissions`,
  `TakeOwnership`) и сами файлы (exe, DLL рядом, `TrayMon.json`, указанный в нём smartctl).
  Непрочитанный ACL запрещает. `Autostart.OwnerOf` владельца показывает, но не блокирует.
- Задача и ярлык принадлежат установке: `Enable` не перезаписывает чужую задачу без
  подтверждения, `Disable`/`Uninstall` её не удаляют, ярлык удаляется после проверки `TargetPath`.
  Состояние — `Autostart.State` (действие, `Enabled`, logon-триггер, учётная запись); галочка
  меняется после успешной операции и повторного чтения.
- `Environment.ProcessPath` — не путь к программе (при `dotnet TrayMon.dll` это `dotnet.exe`).
  `Autostart.ExePath` ищет apphost; без него установочные действия отказываются.
- Внешние программы — по полному пути (`%SystemRoot%\System32\notepad.exe`); `nvml.dll` — через
  `NativeLibrary.SetDllImportResolver`, который при ненахождении **бросает**, а не возвращает
  `IntPtr.Zero`. Относительные `Tools.Smartctl` и `Log.Path` — от папки программы.
- `smartctl.exe` не запускается, только если папка программы защищена, а инструмент из
  `TrayMon.json` лежит в более слабом месте; иначе запуск и запись в `HddSensor.Note`.
- Драйвер WinRing0 (CVE-2020-14979) — принятый риск, записан в обеих README: после `Open()` проба
  чтения, при неудаче `DriverBlocked`; DACL `\\.\WinRing0_1_2_0` сужается до Administrators/SYSTEM.
  Переход на LHM ≥ 0.9.5 с PawnIO — новое требование установки (обе README) и замер `ReadSlow`.
- На админский токен завязаны три вещи, поэтому манифест не упрощать до `asInvoker`: драйвер
  датчиков (MSR, износ NVMe); задача с `RunLevel HighestAvailable`; открытие `TrayMon.json`
  блокнотом и запись в `%ProgramFiles%`. Температуры дисков сюда не относятся.

## Устройство

Один таймер (`TickMs`, по умолчанию 2 с; при заблокированном сеансе `IdleTickMs` = 30 с), других
потоков с логикой нет. `Tick()` читает дешёвое на месте, тяжёлое — в `Spawn(...)`, всё пишет в
`Readings _r`. Затем цикл по `_families` (массив собран в конструкторе — без выделений на тике),
каждое семейство в своём `try`. `OnTick` защищён `_inTick`; диалоги из тика — в очередь `Later`.

`Show*()`: `Slot(id, metric, guid)` → `Record()` (живость и `Stats`) → `Show()`; после цикла —
`Fade()`. `IconSlot` = `Metric` (цвет, пороги, единицы, пул GUID) + настройки + `Stats` +
`TrayValueIcon`. `Stats` — окно по времени (`Window(now)`, 5 минут), не кольцо; строка статистики
приклеивается в `Tooltip()`.

| Источник | Период | Где |
|---|---|---|
| CPU, память, батарея, uptime | каждый тик | на потоке интерфейса |
| GPU (`GpuEveryMs`) | 4 с | там же |
| сеть и тома (`IoEveryMs`) | 6 с | там же |
| температура CPU и вентиляторы (`SlowEveryMs`) | 6 с | `Spawn` |
| процессы по вводу-выводу (`TopIoEveryMs`) | 12 с | `Spawn`, и только если тома шевелятся |
| ИБП (`UpsEveryMs`) | 30 с | `Spawn` |
| подсказочная статистика (`StatsEveryMs`) | 30 с | на потоке интерфейса |
| температуры и износ дисков (`DiskEveryMs`) | 62 с | `Spawn` |
| свободное место (`SpaceEveryMs`) | 300 с | `Spawn` |
| диски за RAID (`RaidEveryMs`) | 600 с | `Spawn` |

Код в `src/`: `Program.cs` — `--once` и `TrayApp` (тики, слоты, меню, окна, форматирование);
`Pure.cs` — логика без железа под тестами (`GuidPool` + `IGuidStore`, `Stats`, `Alarm`, `Scale`,
`Format`, `Csv`, `Redactor`, `StorageTemperature`); `TrayIcons.cs` — отрисовка и `Shell_NotifyIcon`;
датчики — `PerfSensors.cs` (PDH), `Sensors.cs` (память, батарея, место, NVML, LHM), `DiskSensor.cs`,
`HddSensor.cs` (`smartctl -j`), `UpsSensor.cs` (SNMP, PowerNet MIB вручную); `WindowsLog.cs` —
журнал приложений; `Config.cs` — `TrayMon.json`; `Autostart.cs` — задача, ярлык, проверка прав.

Автозапуск — задача планировщика, которую создаёт сама программа из своего меню. Это часть
продукта: внешнего реестра задач здесь нет, и заводить его не нужно.

## Сборка и проверка

```powershell
dotnet publish src/TrayMon.csproj -c Release -o out
out\TrayMon.exe --once                    # из консоли, открытой ОТ АДМИНИСТРАТОРА
out\TrayMon.exe --once --icons --ticks 3  # плюс несколько тиков слоя иконок
dotnet out\TrayMon.dll --once             # то же без прав: манифест берётся у dotnet.exe
dotnet test tests/TrayMon.Tests/TrayMon.Tests.csproj
sh tools/Test-GitHooks.sh                 # секрет-хуки, во временных репозиториях
```

- Манифест — `requireAdministrator`, из обычной консоли `--once` даёт `ERROR_ELEVATION_REQUIRED`.
  Прогонять оба варианта: отсутствующее железо и недоступные источники обязаны молча пропускаться.
- Под тестами (`tests/TrayMon.Tests`, xunit) — только логика без железа из `Pure.cs`, BER-парсер
  SNMP и `Config` на враждебном файле. Долю покрытия никто не мерил — не называть её.
- Железо, драйверы и оболочка не под тестами. Smoke — `--once`; слой иконок — `--once --icons`:
  настоящий тик `TrayApp` без трея (`Spawn` в `_dry` работает на месте, поэтому его «tick N мс»
  дороже рабочего), `--ticks N` — несколько тиков с паузой. Ненулевой код возврата — исключение в
  слое иконок. Живое меню, RDP и реальные датчики — только руками; dry-run их не проверяет.
- «Процесс жив» — не проверка: правку трея проверяют `Renders`/`ShellCalls` в «Диагностике…».
- `sensor driver: loaded` — библиотека открылась, а не «читает»; для второго есть `BLOCKED`.
- `LibreHardwareMonitorLib` — только из NuGet: DLL из FanControl собрана под netstandard2.0 и
  зовёт перегрузку `Mutex`, которой в .NET 8 нет.
- Свойства в `TrayMon.csproj` — решения, у каждого причина комментарием; не чистить как шаблон.
  `InvariantGlobalization=true`: ICU нет, числа — только через `CultureInfo.InvariantCulture`.
  `<Version>` поднимается при выпуске вместе с `FileVersion` и `InformationalVersion`.

## Язык и публикация

- Интерфейс, подсказки и README — по-русски; имена, комментарии и XML-doc — по-английски.
  Комментарий объясняет **почему**, а не что делает строка.
- README две: [README.en.md](README.en.md) — сокращённая английская, но всё, что меняет поведение
  (значок, идентификатор в `TrayMon.json`, порог, требование к установке), правится в обеих.
  Перед публикацией примеры `--once` сверять `tools\Check-ReadmeOutput.ps1`.
- Репозиторий зеркалится в публичный GitHub: внутренних имён, адресов, путей и учётных данных нет
  нигде. Весь вывод `--once`, включая `--icons` и тексты исключений, идёт через `Redactor` — одно
  место. Полная картина — только в «Диагностике…».
- Секрет-хуки `.githooks`: `commit-msg` сканирует весь файл сообщения; `pre-push` отказывает при
  ошибке git, сканирует аннотированные теги и исключает из подробного прохода только `_scan.sh`;
  денилист ищет одна `scan_denylist_path`, читает одна `scan_denylist_patterns`: файл, который
  есть, но не читается, — отказ, а не пустой список.
- `.sanitize-patterns` чистоту не доказывает: публикация — `/github-push` и чтение диффа глазами.
  `git push` намеренно не предодобрен в `.claude/settings.local.json`.
- `TrayMon.json`, `TrayMon.csv`, `smartctl.exe`, `drivedb.h`, `out/`, `bin/`, `obj/` — не в git.
