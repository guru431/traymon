# AGENTS — TrayMon

Что программа делает — [README.md](README.md). Полные правила — [CLAUDE.md](CLAUDE.md).
Здесь только то, без чего сломаешь продукт.

## Ключевые файлы

- `src/Program.cs` — `--once`, `TrayApp`: тики, слоты иконок, `GuidPool`, меню, окна, форматирование
- `src/TrayIcons.cs` — отрисовка и регистрация значков через `Shell_NotifyIcon`
- `src/PerfSensors.cs`, `src/Sensors.cs`, `src/HddSensor.cs`, `src/UpsSensor.cs` — источники данных
- `src/Config.cs` — `TrayMon.json` рядом с exe
- `src/Autostart.cs` — задача планировщика AtLogOn / HighestAvailable, ярлык, удаление; проверка `WritableByNonAdmins`

## Сборка и проверка

```powershell
dotnet publish src/TrayMon.csproj -c Release -o out
out\TrayMon.exe --once            # все значения + стоимость каждого источника в мс
out\TrayMon.exe --once --icons    # плюс один тик слоя иконок: слот, GUID, что нарисовано
```

Манифест — `requireAdministrator`, поэтому `--once` идёт **из консоли администратора**.
Поведение без прав проверяется через рантайм: `dotnet out\TrayMon.dll --once` — манифест
берётся у `dotnet.exe`, процесс остаётся непривилегированным. Прогонять оба.

Автотестов нет — всё содержательное упирается в железо и оболочку Windows. Роль
smoke-теста играет `--once`, а слой иконок — только `--once --icons`: раздача GUID,
погасание пропавших источников и условное появление значков иначе не проверяются ничем.

**«Процесс жив» — не проверка.** Сломанный P/Invoke к `Shell_NotifyIcon` не регистрировал
ни одного значка, а процесс при этом прекрасно работал, ел память и не падал: исключение
ловил `try/catch` вокруг тика. Если правка касается трея — смотреть на счётчики
`TrayValueIcon.Renders` / `ShellCalls` («Диагностика…»): при отказе регистрации они растут
на порядок быстрее, чем при нормальной работе (~1.5 вызова на тик на весь трей).

## Грабли, специфичные для этого проекта

- **Смысл проекта — цена наблюдения:** 0.52 % ядра против 15.8 % у HWiNFO64. Новый
  источник или более частый опрос — только с замером. Сравнивать сборки надо
  чередующимися прогонами по медиане и **при одинаковом составе значков**: их число
  влияет на цену сильнее, чем код, а разброс одного прогона больше эффекта.
- **`cost, ms` из `--once` — холодный первый вызов, а не установившийся режим,** и по нему
  нельзя сравнивать сборки: на одной правке он показал «улучшение» 19.9 → 8.2 мс там, где
  в установившемся режиме было ухудшение 1.8 → 5.7 мс.
- **Дороже сбора данных — перерисовка и вызов в оболочку.** Они считаются отдельно
  (`Renders`, `ShellCalls`), потому что `cost, ms` их не покрывает.
- **GUID иконок в `Program.cs` не менять и не перенумеровывать.** Windows держит позицию
  значка привязанной к паре «путь к exe + GUID». Суффиксы разложены блоками по десять
  (`01-09` одиночные, `11-14` NVMe, `21-28` вентиляторы, `31-38` тома, `41-44` RAID,
  `51-57` сеть, `61-68` место, `71-7C` GPU); добавлять — внутри своего блока.
- **GUID выдаёт только `GuidPool`, по ключу источника, а не по индексу в списке.** Раздача
  по позиции ломалась от подключённой флешки: буква сдвигала индексы, и новый значок
  сносил чужой. Все семейства обязаны ходить через пул.
- Два экземпляра дерутся за одни GUID, поэтому второй запуск запрещён мьютексом
  `Local\TrayMon.SingleInstance`.
- **Нет значения — слот не живой.** `Record()` отмечает живым только при наличии числа,
  `Fade()` серит остальное и пишет причину в подсказку. Замороженное последнее значение
  исчезнувшего источника — худший вид отказа для монитора.
- Числа на значках огрублены намеренно (целые, обороты в тысячах): каждая изменившаяся
  цифра — перерисовка и вызов в оболочку. Десятые доли живут только в подсказке, и сама
  подсказка не уходит в оболочку, пока на значок не навели мышь.
- Сеть — в мегабитах, а не мегабайтах: в мегабайтах фоновая нагрузка это круглый `0`.
- GPU — через NVML; `IsGpuEnabled = false` у LibreHardwareMonitor присвоено явно
  (68 мс против 4 мс).
- CPU — со счётчика Hyper-V, если он есть: `\Processor Information` на хосте видит только
  корневой раздел и врёт впятеро.
- **Счётчик PDH стоит не столько, сколько кажется:** сбор берёт весь объект, упомянутый
  в запросе. `\System\System Up Time` — одно число, но объект `System` тянет обход таблицы
  процессов, и в общем запросе он поднял цену тика с 1.8 до 5.7 мс. Uptime и `\Process(*)`
  живут в отдельных запросах с редким опросом. Смотри на объект, а не на счётчик, и меряй.
- Периоды опроса не должны иметь общих делителей, иначе тяжёлые чтения сходятся на одном
  тике всегда: `DiskEveryTicks` = 31, а не 30, и у опросов разные фазы.
- Последний значок скрыть нельзя — на значках живёт меню; проверка нужна и в меню, и при
  загрузке файла настроек. У вентиляторов, ИБП и свободного места severity инвертирована.
- Ответ SNMP — враждебные данные: в Windows нет привилегированных портов. Тип PDU,
  request-id и community сверяются, длины TLV проверяются по границе пакета.
- `LibreHardwareMonitorLib` — только из NuGet: DLL из FanControl вызывает перегрузку
  `Mutex`, которой в .NET 8 нет. `Available` означает «библиотека открылась», а не «может
  читать»: без админского токена она открывается и отдаёт `null` на каждую температуру.
- **`InvariantGlobalization=true`** — ICU в сборке нет вовсе: форматирование и разбор чисел
  только через `CultureInfo.InvariantCulture`, культурных форматов в рантайме не существует.
  Там же в `TrayMon.csproj` намеренно включены `AllowUnsafeBlocks` (обход массивов PDH
  указателем) и `PublishReadyToRun` (иначе весь путь опроса джитится сразу после логона).
- **README две штуки.** [README.en.md](README.en.md) — сокращённая английская версия, но
  всё, что меняет поведение (новый значок, идентификатор в `TrayMon.json`, порог, требование
  к установке), правится в обеих. Расходятся они молча.
- Репозиторий зеркалится в публичный GitHub: внутренних имён, адресов и путей в коде и
  документации быть не должно. `--once` печатает обезличенно; полная картина — в пункте
  меню «Диагностика…». `.sanitize-patterns` — не доказательство чистоты, сверка глазами
  по диффу обязательна, `git push` намеренно не предодобрен.
