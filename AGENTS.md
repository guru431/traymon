# AGENTS — TrayMon

Что программа делает — [README.md](README.md). Полные правила — [CLAUDE.md](CLAUDE.md).
Здесь только то, без чего сломаешь продукт.

## Ключевые файлы

- `src/Program.cs` — `--once`, `TrayApp`: тики, слоты иконок, меню, окна, форматирование
- `src/Pure.cs` — `GuidPool`, `Stats`, `Alarm` (уровень тревоги), `Scale`, `Format`, `Csv`,
  `Redactor`, `StorageTemperature`: логика без железа, покрыта тестами
- `src/TrayIcons.cs` — отрисовка и регистрация значков через `Shell_NotifyIcon`, гистерезис цвета
- `src/PerfSensors.cs`, `src/Sensors.cs`, `src/DiskSensor.cs`, `src/HddSensor.cs`,
  `src/UpsSensor.cs` — источники данных
- `src/WindowsLog.cs` — критические переходы в журнал приложений Windows
- `src/Config.cs` — `TrayMon.json` рядом с exe
- `src/Autostart.cs` — задача планировщика через COM `Schedule.Service`, ярлык, удаление;
  `InstallUnsafe` (папка, **все предки** и сами файлы: exe, DLL, `TrayMon.json`, smartctl)
- `tests/TrayMon.Tests` — xunit; `tools/Check-ReadmeOutput.ps1` — сверка примеров README;
  `tools/Test-GitHooks.sh` — регрессии секрет-хуков настоящим `git commit -m`

## Сборка и проверка

```powershell
dotnet publish src/TrayMon.csproj -c Release -o out
out\TrayMon.exe --once                    # все значения + цена источника, холодная и тёплая
out\TrayMon.exe --once --icons --ticks 3  # плюс тики слоя иконок: слот, GUID, что нарисовано
dotnet test tests/TrayMon.Tests/TrayMon.Tests.csproj
sh tools/Test-GitHooks.sh                 # секрет-хуки, во временных репозиториях
```

Манифест — `requireAdministrator`, поэтому `--once` идёт **из консоли администратора**.
Поведение без прав проверяется через рантайм: `dotnet out\TrayMon.dll --once` — манифест
берётся у `dotnet.exe`, процесс остаётся непривилегированным. Прогонять оба.

Тестами покрыто то, что не трогает железо: BER-парсер SNMP (включая пакет, который вешал поток),
`GuidPool` вместе с запоминанием раздачи, `Alarm.LevelOf` с гистерезисом, окно `Stats` по времени,
шкала сводного значка, форматтеры, разбор ответа о температуре диска, `Redactor`, экранирование
CSV, `Config` на враждебном файле. Остальное упирается в железо и оболочку Windows; роль
smoke-теста играет `--once`, а слой иконок — `--once --icons`: раздача GUID, погасание пропавших
источников и условное появление значков иначе не проверяются ничем. Живое меню, RDP и реальные
датчики — только руками. Ненулевой код возврата `--once --icons` = слой иконок бросил исключение.

**«Процесс жив» — не проверка.** Сломанный P/Invoke к `Shell_NotifyIcon` не регистрировал
ни одного значка, а процесс при этом прекрасно работал, ел память и не падал: исключение
ловил `try/catch` вокруг тика. Если правка касается трея — смотреть на счётчики
`TrayValueIcon.Renders` / `ShellCalls` **в «Диагностике…» работающей программы**
(норма ~1.5 вызова на тик на весь трей). В `--once --icons` они по построению нули: трей
там не трогается вовсе, и отчёт dry-run прямо это пишет.

## Грабли, специфичные для этого проекта

- **Смысл проекта — цена наблюдения:** 0.52 % ядра против 15.8 % у HWiNFO64. Новый
  источник или более частый опрос — только с замером. Замер = дельта
  `TotalProcessorTime` **TrayMon и `explorer.exe`** за одно окно плюс `ShellCalls` на тик:
  перерисовка трея происходит в оболочке и в собственный счёт не попадает. Разброс одного
  прогона больше эффекта, поэтому две сборки запускаются **одновременно**, ключом
  `--measure` (снимает мьютекс и регистрирует значки без GUID), при **одинаковом составе
  значков**. Границы этих чисел: они про процессорное время **процессов** и про одну машину;
  «в 55 раз» — отношение суммы двух конкурентов к TrayMon, а не преимущество над каждым;
  общую дельту `explorer.exe` при парном прогоне нельзя приписать одной из двух сборок.
- **`cost, ms` печатается двумя числами, cold / warm.** Холодное — первый вызов, по нему
  сборки не сравнивают: на одной правке оно показало «улучшение» 19.9 → 8.2 мс там, где
  в установившемся режиме было ухудшение 1.8 → 5.7. Тёплое — первое приближение.
- **GUID иконок в `Program.cs` не менять и не перенумеровывать.** Windows держит позицию
  значка привязанной к паре «путь к exe + GUID». Суффиксы разложены блоками по десять
  (`01-0C` одиночные, `0D-0F` свободно, `11-14` диски, `21-28` вентиляторы, `31-38` тома,
  `41-44` RAID, `51-57` сеть, `61-68` место, `71-7C` GPU); добавлять — внутри своего блока.
- **GUID выдаёт только `GuidPool`, по ключу источника, а не по индексу в списке.** Раздача
  по позиции ломалась от подключённой флешки: буква сдвигала индексы, и новый значок
  сносил чужой. Все десять пулов обязаны ходить через него. `Take(...)`/`Math.Min(...)`
  в датчиках запрещены: обрезать источники — работа пула, он же и сообщает о переполнении.
  Раздача **запоминается** в `Config.Slots` через `IGuidStore`: без этого таблица строилась
  заново в порядке первых ответов, и после перезапуска без устройства A его GUID уходил B.
- **Ключи источников должны быть аппаратными.** GPU — хвост UUID из NVML, а не индекс
  (индекс сдвигается при добавлении карты); вентилятор — **всегда** `чип/имя`, а не имя,
  пока оно уникально (ключ переключался при появлении второй микросхемы SuperIO); одинаковые
  модели дисков нумеруются в порядке серийников, а не перечисления. Смена схемы ключа обязана
  переносить прежние настройки — `TrayApp.Migrate` + `Config.Rename`.
- Один GUID — одна живая иконка: второй экземпляр не дублирует значки, а **отбирает** их
  у первого, поэтому второй запуск запрещён мьютексом `Local\TrayMon.SingleInstance`
  (кроме `--measure`).
- **Нет ни значения, ни доказанного состояния — слот не живой.** `Record()` отмечает живым при
  наличии числа **или** severity (ИБП «от батареи» без датчика заряда — именно этот случай),
  `Fade()` серит остальное, пишет причину и последнее значение со временем в подсказку,
  обнуляет `Severity` (иначе сводный значок и CSV считали мёртвый источник) и **создаёт серую
  иконку** для включённого мёртвого слота. Через `ForgetAfterMs` = 24 ч (по стенным часам, не
  по тикам) слот возвращает GUID в пул — но не последний, на котором держится меню. Обеспечивает
  это каждый датчик сам: при отказе он обязан обнулить своё поле, а не оставить прошлое.
- **Свежесть — часть данных.** Каждый фоновый снимок публикуется вместе с
  `Readings.<Источник>At`, и данные старше двух периодов живыми не считаются (`Fresh`/`MaxAgeMs`).
  Без этого зависший читатель выглядел живым: UI-тик заново отмечал слот увиденным из кэша,
  а флаг `_*RefreshRunning` заодно запрещал новые попытки.
- **Форматирование считается всегда, в оболочку уходит только для включённых значков.**
  Иначе «Сводка…» показывает «—» для всех скрытых, а включённый из меню значок висит серым
  до следующей смены версии семейства.
- **Меню живёт на значках.** «Последний значок» для запрета скрытия — `CarriesMenu`
  (`Enabled && Icon is not null && Icon.Registered`): объект иконки без подтверждения оболочки
  меню не несёт. А `EnsureSomethingVisible()` спрашивает **только `Enabled`** и вызывается каждый
  тик: спроси он про регистрацию — занятая при логоне оболочка получила бы включение лишних
  значков и диалог каждые две секунды.
- **Уровень тревоги считается в одном месте** — `Alarm.LevelOf` (−2 неизвестно, −1 нет данных,
  0/1/2). Из него берут цвет плашки, уголки, журнал, уведомление и сводный значок. Три
  независимых расчёта расходились: при 85 → 82.9 плашка была красной, а сводная жёлтой.
  `TrayValueIcon` пороги больше **не знает** — ему передают уровень.
- Числа на значках огрублены намеренно (целые, обороты в тысячах, ТБ от 1000 ГБ, Гбит/с от
  10000 Мбит/с), округление **от нуля** — как в подсказке. Цвет плашки огрублён гистерезисом:
  тревога снимается только ниже порога на 3 % шкалы. Подсказка не уходит в оболочку, пока на
  значок не навели мышь. Значок создаётся готовым — один `NIM_ADD`, без серой вспышки.
  Пятизначных чисел не должно быть: единица переходит на шаг выше и пишется в подписи.
- Сеть — в **десятичных** мегабитах (10⁶): в мегабайтах фоновая нагрузка это круглый `0`,
  а деление на 1024² печатало гигабитный порт как 954. Загрузка канала — по более
  нагруженному направлению, не по сумме.
- Температуры дисков — `IOCTL_STORAGE_QUERY_PROPERTY`, без драйвера ядра и без прав
  администратора. Библиотека датчиков осталась только ради износа и резерва NVMe.
- GPU — через NVML; `IsGpuEnabled = false` у LibreHardwareMonitor присвоено явно
  (68 мс против 4 мс). CPU — со счётчика Hyper-V, если он есть: `\Processor Information`
  на хосте видит только корневой раздел и врёт впятеро.
- **Счётчик PDH стоит не столько, сколько кажется:** сбор берёт весь объект, упомянутый
  в запросе. `\System\System Up Time` — одно число, но объект `System` тянет обход таблицы
  процессов, и в общем запросе он поднял цену тика с 1.8 до 5.7 мс. Этот счётчик убран
  совсем (`GetTickCount64` бесплатен), урок остался, живая иллюстрация — `\Process(*)`
  в отдельном запросе. Смотри на объект, а не на счётчик, и меряй.
- **Периоды опроса — в миллисекундах, не в тиках** (`*EveryMs` + `Due(ref at, period)`).
  В тиках «30 с» у ИБП превращались в 450 при `TickMs` = 30000 и при заблокированном сеансе,
  а события журнала Windows нужны именно тогда, когда никто не смотрит. Прежнего правила про
  фазы больше нет, и оно было неверным: совпадение возможно ⇔ фазы равны по модулю **НОД**,
  а не любого общего делителя, и 31 против 3 (взаимно простые) его нарушали. Настоящая цель —
  не блокировать UI (всё тяжёлое в `Spawn`), не входить в библиотеку датчиков дважды (её
  блокировка) и не накладывать медленный ответ на следующий (`_*RefreshRunning`).
- **Тяжёлое читается в `Spawn(...)`** под флагом `_*RefreshRunning`, чтобы медленный ответ
  не наложился на следующий. Флаг — `Interlocked.Exchange`, а не `bool`: проверка
  с последующей установкой не атомарна ровно в том случае, ради которого флаг и заведён.
  В сухом прогоне `Spawn` выполняет работу **на месте** — чтобы `--once --icons` шёл тем же
  путём публикации (версии, штампы), а не своим.
- **В семействах с версионированием версия читается до данных** (диски, RAID, ИБП): фон
  пишет список и **потом** инкрементирует версию, читать надо в обратном порядке. Иначе
  пара «старый список + новая версия» запоминается как уже показанная — отставание
  до 62 с у NVMe и до 600 с у RAID.
- **У инвертированных метрик две разные инверсии.** `Metric.Inverted` (ИБП, батарея) —
  пользователь думает зарядом, хранится `100 − x`, и диалог порогов обязан это делать.
  `Metric.StallAlarm` (вентиляторы) — severity 0/100, порогов нет вовсе. Свободное место
  не инвертировано: пороги и severity там одинаково «% занято».
- Выключенная подсветка — флаг `Alerts: false`, а не пороги `1e9`: константа протекала
  в пользовательский файл и уничтожала настроенные пороги. Передавать `1e9` в отрисовку тоже
  нельзя: severity сыплющегося диска равна той же `1e9`, и сравнение `s >= crit` красило его
  красным при выключенной подсветке. Поэтому уровень решает `Alarm.LevelOf` с флагом.
- **Пороги валидируются до изменения настроек** и одинаково в диалоге и в `Config`: конечность
  (`double.TryParse` принимает `NaN`/`Infinity`), диапазон и warn < crit. Диалог раньше писал
  пару в настройки, а потом обнулял её — и стирал прежние пороги.
- **Старая пара `Warn = Crit = 1e9` — это «подсветка выключена», а не мусор.** Валидация сперва
  браковала её и тем самым включала подсветку там, где её выключили (поймано на живой машине,
  4 значка). Переносить в `Alerts: false`, а не отбрасывать; константа одна — `Alarm.Never`.
- **`LoadError` ≠ `LoadNote`.** Первое — «файл не прочитан» (умолчания, отказ применить reload,
  модальное окно на втором тике), второе — «прочитан, но значение поправлено» (строка в
  «Диагностику…» и `--once`, без диалога). Одно поле на оба случая врало пользователю и ломало
  автоперечитывание.
- **Уведомление о впервые обнаруженной аварии не глотается.** «Возврат из молчания — не
  тревога» верно для −1, но не для −2 «ещё ничего не знали»: сыплющийся при старте RAID,
  заполненный том и уже работающий от батареи ИБП обязаны сообщить о себе. Все уведомления —
  через `Notify()`, он же соблюдает `NotifyOnCritical` и не даёт двух сообщений на одно событие.
- Шкала сводного значка кусочно-линейная (`Scale.Score`): 78 — жёлтый порог любой метрики,
  100 — её красный, при любых пользовательских порогах.
- Ответ SNMP — враждебные данные, но точность формулировки важна: сквоттер на
  `127.0.0.1:161` получает и наш запрос, поэтому сверка PDU/request-id/community отсекает
  **чужие датаграммы**, а не его. От него защищает ограниченность парсера (границы TLV,
  строгое продвижение курсора) и то, что соврать он может только про ИБП.
- Автозапуск — COM `Schedule.Service`, без XML в `%TEMP%`: файл там был окном для подмены
  `<Command>` перед чтением процессом с админским токеном. Задача создаётся только из папки,
  недоступной на запись обычному пользователю — и проверяются **сами файлы тоже** (exe, DLL
  рядом, `TrayMon.json`, указанный в нём smartctl): у файла внутри защищённой папки может быть
  свой ACL. Непрочитанный ACL теперь **запрещает** создание задачи: проверка, которая молча не
  состоялась, не должна выглядеть как пройденная. `Autostart.OwnerOf` владельца лишь показывает
  и не блокирует — надёжно решить отсюда, администратор ли произвольный SID, нельзя.
- **Состояние задачи — не «путь первого действия».** `Autostart.State` проверяет действие,
  `Enabled`, включённый logon-триггер и учётную запись; галочка меняется только после успешной
  операции и повторного чтения. Имя задачи общее для всех установок, поэтому чужую задачу и
  чужой ярлык нельзя перезаписывать или удалять без подтверждения.
- **Запрет запускать внешний инструмент должен что-то покупать.** Первая версия проверки не
  запускала `smartctl.exe` из папки, доступной на запись обычному пользователю, — и на боевой
  машине молча убрала температуры дисков за RAID. Рядом в той же папке лежат `TrayMon.exe` и
  его DLL: запрет не менял риск, а отнимал функцию. Отказ — только когда папка программы
  защищена, а инструмент из `TrayMon.json` лежит в более слабом месте; иначе запуск + запись
  в `HddSensor.Note`. Задача автозапуска из такой папки не создаётся по-прежнему.
- **`Environment.ProcessPath` — не путь к программе.** При запуске через рантайм это
  `dotnet.exe`, и задача/ярлык уезжали на него. `Autostart.ExePath` ищет apphost рядом со
  сборкой, а если его нет — установочные действия отказываются работать.
  Внешние программы — по полному пути (`%SystemRoot%\System32\notepad.exe`); `nvml.dll` — через
  `SetDllImportResolver`, который при ненахождении **бросает исключение**, а не возвращает
  `IntPtr.Zero`: ноль возвращал имя в обычный поиск, то есть в папку приложения.
- `LibreHardwareMonitorLib` — только из NuGet: DLL из FanControl вызывает перегрузку
  `Mutex`, которой в .NET 8 нет. `Available` означает «библиотека открылась», а не «может
  читать»: без админского токена она открывается и отдаёт `null` на каждую температуру,
  а её драйвер WinRing0 может быть заблокирован HVCI — для этого есть `DriverBlocked`.
- **`InvariantGlobalization=true`** — ICU в сборке нет вовсе: форматирование и разбор чисел
  только через `CultureInfo.InvariantCulture`. Там же в `TrayMon.csproj` намеренно включены
  `AllowUnsafeBlocks`, `PublishReadyToRun`, `RollForward`, `DebugType embedded`,
  выключен конкурентный GC и стоит цель, вычищающая чужие `runtimes\` из publish.
- **README две штуки.** [README.en.md](README.en.md) — сокращённая английская версия, но
  всё, что меняет поведение (новый значок, идентификатор в `TrayMon.json`, порог, требование
  к установке), правится в обеих. Расходятся они молча. Примеры вывода сверяются
  `tools\Check-ReadmeOutput.ps1`.
- Репозиторий зеркалится в публичный GitHub: внутренних имён, адресов и путей в коде и
  документации быть не должно. `--once` печатает обезличенно — **весь вывод идёт через
  `Redactor`**, включая отчёт `--icons` и текст исключений: серийники, подписи и пути жили
  именно там. Полная картина — в пункте меню «Диагностика…». `.sanitize-patterns` — не
  доказательство чистоты, сверка глазами по диффу обязательна, `git push` намеренно
  не предодобрен.
- Секрет-хуки: `commit-msg` сканирует **весь файл сообщения**, включая строки с `#` —
  `$2` ему не передаётся вовсе (это аргумент `prepare-commit-msg`), и ветка со срезанием
  комментариев срабатывала всегда, а `git commit -m` такие строки сохраняет. `pre-push`
  проверяет коды возврата `rev-list`/`cat-file`/`log` и **отказывает** при ошибке, сканирует
  сообщения аннотированных тегов и исключает из подробного прохода только `_scan.sh`.
  Денилист ищется одной общей функцией `scan_denylist_path` (в linked worktree он лежит
  у главного checkout).
