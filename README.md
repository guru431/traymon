# TrayMon

Показывает загрузку и температуры машины прямо в области уведомлений Windows — числами
на иконках, без окон и графиков. Написан как замена связке HWiNFO64 + AIDA64, которые
на одном сервере съедали около 30 % ядра просто за то, что висели открытыми.

| | CPU | Private RAM |
|---|---|---|
| **TrayMon** (17 иконок) | **0.52 %** ядра | 48 МБ |
| HWiNFO64 | 15.8 % | 19 МБ |
| AIDA64 | 13.7 % | 25 МБ |

Замер в одном окне 120 секунд на одной и той же машине. По памяти TrayMon проигрывает —
это цена рантайма .NET; по процессору дешевле примерно в 55 раз.

## Что показывает

Одна иконка — одно число. Цвет плашки говорит, что за метрика, так что их можно различить,
не читая цифр:

| Иконка | Значение | Плашка | Жёлтая / красная при |
|---|---|---|---|
| CPU | загрузка, % | синяя | 70 / 85 % |
| RAM | занято, ГБ | зелёная | 80 / 90 % объёма |
| GPU | загрузка ядра, % | бирюзовая | 75 / 90 % |
| VRAM | занято видеопамяти, ГБ | фиолетовая | 75 / 90 % объёма |
| NET | сеть, МБ/с (приём + передача) | пурпурная | 70 / 90 % полосы |
| C: D: … | нагрузка тома, МБ/с (чтение + запись) | оливковая | не подсвечивается |
| °C | температура CPU | стальная | 75 / 85 °C |
| °C | температура GPU | тёмно-фиолетовая | 80 / 90 °C |
| °C ×N | температура каждого NVMe | коричневая | 60 / 70 °C |
| °C ×N | температура диска за RAID-контроллером | янтарная | 55 / 65 °C |
| об/мин ×N | скорость каждого вентилятора | сине-стальная | остановка (0) |

Подсказка у каждой иконки своя и содержит подробности: у RAM — гигабайты и процент,
у диска — чтение и запись отдельно плюс три процесса с наибольшим вводом-выводом,
у вентилятора — точные обороты и заданный процент.

Числа намеренно огрублены: обороты в тысячах (`0.6` — это 586 об/мин), скорости целыми
МБ/с. Каждое изменение цифры стоит перерисовки и вызова в оболочку — на замере пять иконок,
мигавших десятыми долями, обходились в 0.66 % ядра, втрое дороже сбора самих данных.

**У вентиляторов логика цвета обратная:** тревожна остановка, а не высокие обороты, поэтому
плашка краснеет при нуле.

## Настройки

Правый клик по любой иконке:

- **Цвет фона…** — свой цвет для этой иконки
- **Переименовать…** — своя подпись в подсказке
- **Подсвечивать при перегрузке** — снятая галочка означает, что плашка всегда своего цвета
- **Скрыть этот значок**
- **Показывать значки ▸** — список всех, включая скрытые
- **Запускать при входе в Windows**
- **Создать ярлык на рабочем столе**
- **Настройки в файле…**

Всё пишется в `TrayMon.json` рядом с exe:

```json
{
  "Icons": {
    "cpu": { "Enabled": true, "Color": "#1C5CA8" },
    "ram": { "Enabled": true, "Color": "#408080", "Warn": 88, "Crit": 95 },
    "fan.Fan #1": { "Enabled": true, "Label": "CPU fan" },
    "disk.0": { "Enabled": false }
  }
}
```

Идентификаторы: `cpu`, `ram`, `gpu`, `vram`, `cpu.temp`, `gpu.temp`, `disk.<номер>`,
`disk.raid.<серийник>`, `fan.<имя датчика>`, `fan.gpu`, `net`, `vol.<буква диска>`.

Скрыть **все** иконки нельзя: меню живёт на них, и без последней не осталось бы способа
даже выйти из программы.

### Если выбранный цвет не появился

Пороговая подсветка перекрывает цвет плашки: пока значение выше порога предупреждения,
иконка жёлтая или красная, какой цвет ни выбери. Пороги задаются полями `Warn`/`Crit`
или снимаются галочкой в меню. Программа сама предупредит, если вы выбрали цвет иконке,
которая сейчас подсвечена.

## Откуда берутся данные

| Метрика | Источник | Период | Цена опроса |
|---|---|---|---|
| CPU загрузка | PDH: `\Hyper-V Hypervisor Logical Processor(_Total)` или `\Processor Information(_Total)` | 2 с | 3 мс |
| RAM | `GlobalMemoryStatusEx` | 2 с | 1 мс |
| GPU: загрузка, память, температура, обороты | `nvml.dll` (P/Invoke) | 4 с | 4 мс |
| CPU температура | LibreHardwareMonitorLib | 6 с | 20–45 мс |
| Вентиляторы | LibreHardwareMonitorLib, SuperIO | 6 с | 5 мс |
| Сеть, нагрузка томов | PDH: `\Network Interface(*)`, `\LogicalDisk(*)` | 6 с | 6 мс |
| Процессы с наибольшим вводом-выводом | PDH: `\Process(*)\IO Data Bytes/sec` | 12 с | 12 мс |
| Температуры NVMe | LibreHardwareMonitorLib, SMART | 60 с | 6 мс |
| Температуры дисков за RAID | `smartctl.exe` (внешний процесс) | 600 с | ~90 мс на диск |

Три решения, ради которых всё это и писалось:

**CPU берётся у гипервизора, если он есть.** На хосте Hyper-V счётчик `\Processor Information`
видит только корневой раздел: он показывал 13 % при реальной загрузке железа 65 %.

**GPU читается через NVML, а не через библиотеку датчиков.** У LibreHardwareMonitor один
опрос GPU стоит 68 мс против 4 мс у NVML, поэтому `IsGpuEnabled` намеренно выключен.

**Диски за RAID-контроллером** не отдаёт ни один API Windows — массив виден системе одним
устройством. Их читает `smartctl` из [smartmontools](https://www.smartmontools.org/) через
CSMI. Устройства ищутся сами (`--scan-open -d csmi`) и дедуплицируются по серийному номеру:
некоторые драйверы отвечают одним и тем же диском на нескольких портах.

## Порядок иконок

Каждая иконка регистрируется через `Shell_NotifyIcon` со своим `guidItem`, а не средствами
WinForms `NotifyIcon`. Без GUID трей Windows 11 считает все иконки процесса одной группой и
таскает их вместе — переставить их между иконками других программ нельзя. С GUID каждая
иконка самостоятельна: её позицию можно задать мышью, и она переживает перезапуск.

**GUID в `Program.cs` менять нельзя.** Windows держит позицию иконки в
`HKCU\Control Panel\NotifyIconSettings` привязанной к паре «путь к exe + GUID». Новый GUID —
новая иконка в конце очереди, со сброшенной настройкой видимости. По той же причине после
переноса exe в другую папку иконки придётся вытаскивать из переполнения заново.

## Требования

- Windows 10 / 11 / Server 2019+ (x64)
- [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0)
- **Права администратора** — температуры CPU и NVMe читаются через драйвер датчиков.
  Без повышения всё остальное работает, температур не будет
- необязательно: `smartctl.exe` рядом с exe — для дисков за RAID-контроллером
- необязательно: драйвер NVIDIA — для метрик GPU

## Автозапуск

Пункт меню «Запускать при входе в Windows» создаёт задачу планировщика: триггер AtLogOn,
LogonType Interactive, RunLevel Highest.

Именно задача, а не ярлык в автозагрузке: программе нужен админский токен, манифест просит
`requireAdministrator`, и ярлык вызывал бы запрос UAC при каждом входе. Задача с Highest — нет.

## Перенос на другую машину

Программа определяет железо сама и молча пропускает то, чего нет:

| Отсутствует | Что будет |
|---|---|
| счётчик Hyper-V | берётся обычный `\Processor Information` |
| драйвер NVIDIA | нет иконок GPU, VRAM и вентилятора видеокарты |
| права администратора | нет температур CPU и NVMe, нет вентиляторов |
| `smartctl.exe` | нет температур дисков за RAID |
| RAID-контроллер | то же — поиск устройств ничего не находит |

Диски, тома, вентиляторы и адаптеры перечисляются динамически: сколько нашлось, столько
иконок и будет. Заранее ничего прописывать не нужно.

Единственная эвристика, которая может не подойти: первый разъём SuperIO подписывается как
`CPU fan`. Чипы назначение разъёмов не сообщают, на большинстве десктопных плат первый —
процессорный. Если это не так, иконка переименовывается через меню.

## Ограничения

- Только Windows и только x64
- Трёхзначные значения (RAM 156, CPU 100 %) рисуются шрифтом помельче — 16 пикселей на три
  цифры немного, но читаемо
- Пределы: 4 NVMe, 4 диска за RAID, 8 вентиляторов, 8 томов — по числу заготовленных GUID
- Состояние самого RAID-массива программа не проверяет, только температуры дисков
